# Чек-листы СМП

## 1. Smoke-тестирование

### Запуск

- [ ] `docker compose up -d` запускает сервисы, PostgreSQL и RabbitMQ.
- [ ] `docker compose ps` показывает, что контейнеры работают.
- [ ] `./scripts/smoke-test.sh` заканчивается сообщением ` ALL CHECKS PASSED`.

### Доступность сервисов

- [ ] Gateway (`:8080/health`) отвечает 200.
- [ ] Card Management (`:8081/health`) отвечает 200.
- [ ] Switch (`:8082/health`) отвечает 200.
- [ ] Authorization (`:8083/health`) отвечает 200.
- [ ] Merchant Simulator (`:8084/health`) и Terminal Simulator (`:8085/health`) отвечают 200.
- [ ] Transaction Logger (`:8088/health`) отвечает 200.
- [ ] Bin Lookup (`:8096/actuator/health`) и Notification Service (`:8097/actuator/health`) отвечают 200.
- [ ] Dashboard открывается на `:3000`, интерфейс RabbitMQ  - на `:15672`.

### Быстрая проверка данных

- [ ] `POST /api/cards/generate` создаёт не меньше 20 тестовых карт.
- [ ] `GET /api/cards` возвращает список созданных карт.
- [ ] `POST /api/simulator/terminal/run` отправляет тестовые транзакции.

## 2. Критический путь

Проверяем основную покупку и причины отказа. Для каждого отказа берём отдельную карту или возвращаем ей исходные данные.

### Card Management

- [ ] Создание карты возвращает PAN из 16 цифр, который проходит алгоритм Луна; статус `ACTIVE`, срок  - текущая дата + 3 года.
- [ ] `GET /api/cards/{pan}` находит созданную карту; для отсутствующей карты возвращает 404.
- [ ] Список карт учитывает `limit`, `offset`, `status` и `bin`; карта со статусом `DELETED` в список не попадает.
- [ ] `PATCH /api/cards/{pan}` меняет переданные поля карты.
- [ ] `DELETE /api/cards/{pan}` меняет статус на `DELETED`; после этого карта не возвращается в GET.
- [ ] Генератор создаёт указанное число карт и распределяет их по переданным BIN.

### Authorization

- [ ] Для действующей карты с достаточными лимитами и балансом возвращается `APPROVED` и код `00`.
- [ ] После одобрения `reserve` уменьшает `availableBalance`, дневной и месячный расход обновляются.
- [ ] RRN содержит 12 цифр, authCode  - 6 символов из букв A–Z и цифр.
- [ ] Неизвестная карта получает отказ `14`; карта `INACTIVE`  - `CARD_INACTIVE`, `BLOCKED`  - `CARD_BLOCKED`, `EXPIRED`  - `54`.
- [ ] Истёкший срок даёт отказ `54`, превышение дневного лимита  - `61`, нехватка средств  - `51`.
- [ ] При превышении месячного лимита покупка отклоняется (код в ТЗ не указан).
- [ ] Если Card Management недоступен, возвращается отказ `05` с причиной `ISSUER_TIMEOUT`.
- [ ] Если Bin Lookup недоступен, Authorization использует `issuerId` от Switch.
- [ ] После отказа деньги не резервируются и расход по лимитам не увеличивается.
